# 星播影院 APP 网站扩展 0.2

此包用于苹果 CMS V10 网站。APP 注册调用网站原有 User 模型，账号直接创建在网站用户表中；网站已有账号也可登录 APP。不是两份账号相互复制。

当前尚未部署到 xbxx.pro。请先在站点备份或测试环境完成下面步骤，再做正式联调。无需把数据库账号、密码填写进 APP。

## 安装

1. 备份网站文件和数据库。在网站文件管理器中确认含有 `api.php` 的网站根目录。
2. 将包中的 `application/api/controller/Xingbo.php` 上传到网站同名目录，将 `application/extra/xingbo.php` 上传到网站同名目录。只添加这两个文件，不替换整个 application 文件夹。如果已有同名文件，先核对并备份。
3. 查看网站现用数据库表前缀。`install.sql` 默认前缀为 `mac_`；如果实际为其他前缀，先替换 SQL 中的 `mac_`。在该网站的数据库中导入 SQL，只会新增四张 `xb_` 扩展表，不迁移或清空已有用户。
4. 将网站 `application/extra/xingbo.php` 中 `'enabled' => false` 改为 `'enabled' => true`。保留网站现有 PHP 版本，扩展依赖 PDO/MySQL、mbstring 和 PHP session。不要为了本扩展直接升级生产 PHP。
5. 在苹果 CMS 后台清理站点缓存。用户系统、开放注册、图形验证码、注册审核仍使用网站现有设置。若网站强制短信或邮件验证，此版本提示去网站注册，不绕过验证。
6. 浏览器打开 `https://xbxx.pro/api.php/xingbo/health`。应返回 `code: 1`。若 404，检查文件位置和 API 路由；若 503，检查配置、四张表和表前缀。
7. 安装新版 APP，在“我的”中重试连接，然后按下面验收清单检查。服务不通时现有公共影片接口仍可使用。

## 上线验收

- 用测试用户名从 APP 注册，在网站后台用户列表确认出现同一个账号，再用该账号登录网站。
- 用网站已有普通账号登录 APP。错误密码必须失败，重复用户名必须失败。
- 开启验证码时确认图片可见且错误验证码无法提交。网站关闭注册时 APP 不能创建账号；需要审核的账号未审核前不能登录。
- 退出并重开 APP，确认有效登录可恢复；退出登录后恢复游客记录，两个账号的本机记录分别保存。
- 在设备 A 播放一段后暂停；设备 B 登录同一账号，从“我的”同步记录，再打开影片确认线路、集数、秒数一致。
- 找片页按年份、地区、语言筛选，切换排序和翻页，结果应来自全站。影片更新在刷新/重新加载列表时读取，不需要重新安装 APP。
- 登录后发送弹幕，审核后在同一影片同一集相应时间出现；未登录和过快发送应失败。
- 在真实安卓手机测试应用小窗、拖动、关闭、返回详情以及桌面小窗；系统小窗需要设备支持并允许画中画。系统小窗使用原生播放器，不显示 Flutter 弹幕层。

## 弹幕审核

默认先审后显示。当前没有新增苹果 CMS 后台审核页面，可在数据库管理器打开 `mac_xb_danmaku`，按 `status=0` 查待审内容，将指定记录改为 `status=1` 通过，改为 `status=2` 隐藏。表前缀按实际替换。需要立即显示时，可在配置中把 `danmaku_review` 改为 `false` 后清理缓存；这只影响之后发送的内容，已有待审记录仍需处理。

## 数据和限制

- 登录令牌默认有效 30 天，服务端只保存令牌摘要；APP 使用系统安全存储。改密码或停用账号后，后续认证请求会失效。
- 观看进度保存在扩展表中，支持 APP 各设备同步；尚未修改网站播放器，因此网站网页播放器的秒级进度不会自动与 APP 互通。网站账号互通不代表所有历史数据自动互通。
- 收藏按账号保存在本机，尚未云端同步。离线进度保存在本机，不自动回放旧的上传请求覆盖另一设备的新进度。
- 每部影片一条续播记录，最近 100 部；同时播放时最后收到的上传优先。线路名称和集数用于续播定位，网站重排集数可能需要手动重选。
- 不含付费会员、支付和下载。受密码或积分限制的影片不由本扩展提供播放授权。
- 接口默认 HTTPS；反向代理应保留 Authorization 请求头。限流用服务器 REMOTE_ADDR；代理站点需正确配置可信代理真实 IP，不能盲目信任客户端传入的转发头。
- 不要把 `tests`、本说明或 SQL 文件上传到公开网站目录。网站只需要两个 PHP 文件和数据库导入。

## 回退

将 enabled 设为 false 并清理缓存即可关闭扩展。保留扩展表不会影响原用户系统；无需删表或清空用户。旧版 APP 的公共影片接口继续使用。

## 已做与待做验证

PHP 语法检查及 13 项隔离契约检查通过，覆盖调用 CMS 注册/登录、权限字段白名单、无效凭据、令牌摘要、请求方法、排序参数和关闭状态。测试使用替身，不连接真实 CMS 数据库。生产注册、验证码、审核、数据库读写与跨设备同步必须部署后按上方清单联调，不能视为已通过。

开发者可在本地运行：`php -d extension=mbstring tests/contract.php`。
